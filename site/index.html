Connectors shouldn't stop at the chat window

Connectors give Claude access to your tools, but only inside Claude. Every other agent re-authenticates each service in its own MCP client, keeps its own tokens, and pays schema tokens up front. Scripts can't use connectors at all.

01One login, every agent

Connect a service once in claude.ai. Codex, Gemini CLI, pi, Hermes, OpenCode and your scripts can all call it. No new OAuth, no API keys, and no third party holding your tokens.

02Safe by default

Read-only unless a policy profile says otherwise. Writes need a plan, its exact hash and an idempotency key. They're never retried, always audited, and refused from inside agent sessions.

03Deterministic

The same command makes the same call, with no model in the loop. Cron jobs, CI checks and batch pipelines just work, and every run proves it cost $0 and 0 tokens.

04New connectors, no wrappers

When a connector appears in claude.ai, plugboard refresh makes it a command. There's no community MCP server to wait for, and no CLI to write.

How it works

Plugboard drives Claude Code's JSON control protocol directly. Claude Code makes the call with the connections you already set up; Plugboard never sees a token.

Any agent or scriptruns plugboard slack …
→
Plugboardchecks the policy, validates the flags against the tool's schema, keeps the audit log
→
Claude Codecalls the claude.ai connector with your login. No model is involved.

Agents find tools on demand with plugboard find and --help, so nothing sits in their context until it's needed. With --axi they get compact AXI output with next-step hints.

The agent proposes. A human approves.

A write sends only the exact bytes someone approved. If the payload changes by a single byte, the hash no longer matches and nothing is sent.

# 1. draft: prints the payload and its hash, sends nothing
$ plugboard slack send-message --arg-file reply.json --as executor --plan

# 2. a human checks it, then sends exactly that payload
$ plugboard slack send-message --arg-file reply.json --as executor \
    --write --write-key reply-42 --expect-hash sha256:8c6f…

Where it fits

Plugboard isn't the only way to give agents tools. It's the one that reuses what you already connected.

CallsYou authenticateReaches claude.ai connectors
PlugboardThe connectors in your claude.aiOnce, in claude.aiYes
MCPorterAny MCP server you configurePer server, in its vaultNo
Composio / RubeA hosted catalog of appsOnce, and they hold the tokensNo
Native harness MCPServers configured in that harnessPer server, per harnessClaude Code only

MCPorter calls the MCP servers you configure. Plugboard calls the connectors you already have. They work fine side by side.

Read this before you depend on it.
  • Plugboard drives an internal, undocumented Claude Code interface. It can break with any update; plugboard doctor tells you when.
  • It is not affiliated with or endorsed by Anthropic, and using connectors this way may not be covered by their terms.
  • You need macOS or Linux, and Claude Code logged in with a claude.ai account that has the connectors you want.
  • Tool output is data. Don't let one agent's results steer another's writes without a human in between.
